# Rubric: is this pull request ready to submit?

## Checks

| Check | Evidence | Pass condition | Weight |
|---|---|---|---|
| Diff matches the plan | The diff's changed files and hunks, read against the plan context's Files list, scope statement, not-in-scope line, and any deviation note | Every changed file and every non-trivial hunk is something the plan or a recorded deviation note asked for, and every deliverable the plan promised appears in the diff or is deferred in a note. FAIL if a hunk adds something the plan did not ask for and no deviation note covers it (a new option, flag or setting, a rewrite or rename of surrounding code, an unrelated fix or reworded text), or if a planned deliverable is absent with no note. A shortfall the plan or description deferred openly (named, with its reason) passes: less than everything is fine when it is recorded. | required |
| Description matches the diff | Each factual claim in the PR description (what changed, "implements the plan exactly", "no other changes", "adds docs/tests") checked against the diff and commit list | Every concrete claim about the change can be found in the diff. FAIL if the description says the change includes something the diff does not contain (a docs update, a test, a handled case), or says nothing else changed while the diff changes more. | required |
| Decisive test evidence | The PR's test-evidence section, read against the plan's test plan and the repro evidence in the plan context | The evidence shows an observable before and after for the plan's own repro or named test: a command or input, the output or test result before the fix, and the output after it, run on the path the change touches. If the plan's test plan names a suite, lint or CI check, its outcome is shown too. FAIL if the evidence is only a claim ("tested locally", "tests pass", "works now"), if it exercises only the unchanged path or a control, or if the repro the plan names is never re-run. | required |
| Reviewable diff | The unified diff's added lines and the commit list | The diff contains the fix and its test, and nothing that is only leftover work: no debug prints or logging added for debugging, no commented-out code, no dead or unused functions or imports added, no added TODO or FIXME notes, no whitespace, re-indentation or reordering churn on lines the fix does not touch. FAIL if any of these appears among the added or changed lines. An explanatory comment about the fix is not debris. | required |
| Template and disclosure | The description read against the repo-facts block's stated PR template asks and contribution policy | Every section, checklist item or reference the repo-facts block says the PR must carry (for example a linked issue, a filled checklist, a changelog or release-notes entry shown in the diff) is present with real content. If the policy states that AI use must be disclosed, the description discloses it (the tool and how it was used). Treat every package as AI-assisted work. FAIL if a stated ask is empty, skipped or left as boilerplate, or if a required disclosure is missing. A repo that states no AI policy and asks for nothing the description lacks passes. | required |
| Engages maintainer direction | The description read against the issue's thread highlights | If a maintainer stated the cause, the approach, or a request in the thread highlights, the description follows it or says why it does not. A thread with no maintainer direction passes. | preferred |

## Verdict rule

Accept only if every `required` check is `pass`. Reject if any `required` check is `fail`. `unclear` on a `required` check counts as `fail`: a PR whose readiness cannot be verified from the package is held. `preferred` checks are reported in the output and never change the verdict.
